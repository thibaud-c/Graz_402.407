# 0. GIS 101: data, analysis, and coordinate systems

[Tutorial index](README.md) · Next: [VS Code](vscode.md)

Allow 75 to 90 minutes for reading and the exercise. No coding experience is needed. Read the concepts first, then use QGIS for the practice at the end. If you already know GIS, use the exercise to check your understanding before moving on to web mapping.

## 1. What is GIS?

A **geographic information system**, or GIS, connects information to locations. We use it to collect, organise, inspect, analyse, and communicate geographic data. A GIS involves people and methods as well as data, computers, and software. A map is one way to display its results.

Consider the question: "Which public places in Graz are near somewhere to rest?" We need locations, information about what is available there, and a definition of "near". GIS lets us compare those records in space. The answer also depends on when the data was collected and which places it includes. [QGIS: introducing GIS](https://docs.qgis.org/3.44/en/docs/gentle_gis_introduction/introducing_gis.html) and [Esri: what is GIS?](https://www.esri.com/en-us/what-is-gis/overview).

A useful workflow is:

1. Ask a geographic question.
2. Find or collect relevant data and inspect its source, date, and licence.
3. Check geometry, attributes, and coordinate systems.
4. Choose an analysis and its parameters.
5. Inspect the result and explain its limits before making a map or sharing data.

## 2. Spatial data: geometry and attributes

For **vector data**, a feature combines geometry and attributes. Geometry describes where something is and its shape. Attributes describe what we have recorded about it. [QGIS: vector data](https://docs.qgis.org/3.44/en/docs/gentle_gis_introduction/vector_data.html).

| Geometry | What it represents | Graz example |
| --- | --- | --- |
| Point | A location | An observation or bus stop |
| Line | A sequence of connected positions | A path, road, or river centreline |
| Polygon | An area enclosed by a boundary | A park or district |

A bench might be a point in a city map and a polygon in a detailed site plan. Choose the representation for the question and scale. A marker's visible size does not tell you the bench's physical size.

Open the existing [practice points](../code_snippets/03_geojson/places.geojson) in VS Code or inspect them in a GIS. They are **invented observations** near central Graz. No knowledge of JSON is needed yet; find the labels and coordinate pairs.

| Feature | Geometry | Attribute `name` | Attribute `category` |
| --- | --- | --- | --- |
| A | Point at longitude 15.4395, latitude 47.0707 | Example stop A | rest |
| B | Point at longitude 15.4420, latitude 47.0760 | Example stop B | shade |
| C | Point at longitude 15.4500, latitude 47.0730 | Example stop C | rest |

In an **attribute table**, a row normally represents a feature and a column is a field. Fields can hold text, numbers, or dates. A missing value means information is absent; it is not automatically zero. Selecting a row usually highlights its geometry on the map. Changing its colour changes its **symbology**, the visual representation, rather than the recorded category. [QGIS: attribute data](https://docs.qgis.org/3.44/en/docs/gentle_gis_introduction/vector_attribute_data.html) and [working with the attribute table](https://docs.qgis.org/3.44/en/docs/user_manual/working_with_vector/attribute_table.html).

## 3. Vector and raster

Vector data represents individual features. **Raster data** uses a grid of cells, also called pixels. Each cell stores a value, and the grid has a location, cell size, and coordinate system. A raster may have several bands, such as red, green, and blue image channels. Its values need not be colours. [QGIS: raster data](https://docs.qgis.org/3.44/en/docs/gentle_gis_introduction/raster_data.html).

| | Vector | Raster |
| --- | --- | --- |
| Structure | Features with coordinates and attributes | Rows and columns of cells with values |
| Examples | Observation points, paths, district boundaries | Satellite imagery, elevation, land-cover classes |
| Typical question | Which points are inside this district? | What is the mean elevation in this district? |
| Detail to inspect | Geometry type, source scale, positional accuracy | Cell size, bands, value units, NoData, positional accuracy |

A 10-metre raster cell covers an area 10 metres wide and 10 metres tall in a suitable metric grid. It does not show the position of every object inside that area. More pixels or more decimal places do not create better source information. **NoData** marks missing or excluded cells; a value of zero may be a valid measurement.

An elevation raster contains height values. A coloured screenshot of an elevation map contains image colours. Check the underlying data before trying to calculate slope or height. The same distinction applies to a WMS image and the features it depicts; see [OGC web services](ogc_webservices.md).

### Layers, files, and projects

A **layer** is a dataset as used in your map, with display settings such as visibility and style. Several layers can refer to the same source. Drawing one layer over another is a visual overlay; calculating their geometric intersection is an analysis.

Common formats include GeoJSON for vector features used on the web, GeoPackage for storing GIS layers in a single file, and GeoTIFF for georeferenced rasters. A Shapefile consists of several companion files, so copying only the `.shp` file can lose attributes or coordinate system information. A GIS project saves references, styles, and map settings; keep its source datasets with it when moving your work. [QGIS: data formats](https://docs.qgis.org/3.44/en/docs/user_manual/managing_data_source/supported_data.html).

## 4. Coordinate reference systems and projections

A **coordinate reference system**, or CRS, tells software how coordinate numbers relate to locations on Earth. It includes a reference for the Earth's shape and position, axes, and units. That Earth reference is often called a **datum**. A projected CRS also includes a map projection and its parameters. [Esri: coordinate systems, projections, and transformations](https://doc.esri.com/en/arcgis-pro/latest/help/mapping/properties/coordinate-systems-and-projections.html).

- A **geographic CRS** uses angular coordinates, usually longitude and latitude in degrees. Longitude locates a position east or west; latitude locates it north or south.
- A **projected CRS** uses a mathematical **map projection** to represent the curved Earth on a flat plane. Coordinates are often eastings and northings in metres, although some systems use feet.

Every map projection introduces distortion. Equal-area projections preserve area relationships; conformal projections preserve local angles. Equidistant projections preserve particular distances, not every distance everywhere. Choose for the location, extent, and purpose of your work. [QGIS: coordinate reference systems](https://docs.qgis.org/3.44/en/docs/gentle_gis_introduction/coordinate_reference_systems.html).

### Three systems you will encounter

An **EPSG code** identifies a CRS in a shared registry. Read its name, units, and area of use rather than memorising the number.

| CRS | Coordinates and units | Use in this course |
| --- | --- | --- |
| WGS 84, EPSG:4326 | Longitude and latitude in degrees | Understand the locations in our GeoJSON examples |
| WGS 84 / UTM zone 33N, EPSG:32633 | Easting and northing in metres | A suitable local system for this introductory buffer exercise around Graz |
| WGS 84 / Pseudo-Mercator, EPSG:3857 | Projected coordinates in metres | The usual display system for the Leaflet basemaps |

UTM divides the world into zones. Zone 33N covers longitudes 12°E to 18°E in the northern hemisphere, including Graz. It is a choice for this local exercise, not a universal Austrian CRS. Official datasets may use another system. [Esri's projected CRS catalogue](https://doc.esri.com/en/arcgis-pro/latest/help/mapping/properties/pdf/projected_coordinate_systems.pdf), entry 32633.

Degree coordinates cannot be used as metre distances in an ordinary planar buffer. Web Mercator has metre units but distorts ground distances and areas, increasingly away from the equator. For our exercise, reproject to UTM 33N before buffering. Other workflows can use documented geodesic methods that account for the Earth's curvature. [Esri: Mercator and Web Mercator](https://doc.esri.com/en/arcgis-pro/latest/help/mapping/properties/mercator.html) and [Buffer methods](https://doc.esri.com/en/arcgis-pro/latest/tool-reference/analysis/buffer.html).

Coordinate **order** also matters. Our GeoJSON stores `[longitude, latitude]`, such as `[15.4395, 47.0707]`. Leaflet's ordinary marker calls use `[latitude, longitude]`. A CRS name alone does not tell you every format or library's array convention. The [GeoJSON tutorial](geodata.md) explains the conversion.

### Assign, display, or reproject?

These actions do different jobs:

| Action | What changes | When to use it |
| --- | --- | --- |
| Assign or define a source CRS | The interpretation of existing numbers | Metadata is missing or wrong, and you know the actual source CRS |
| Change the project or map CRS | How layers are displayed together | Choose the map's view; correctly described layers can transform on the fly |
| Reproject a dataset | Coordinate numbers in a new output dataset | Prepare data in an appropriate common CRS for analysis or export |

Assigning UTM to degree coordinates does not convert them into metres. Reprojection needs the correct source CRS first. When a layer appears in the wrong place, check its metadata and a known location before changing anything. [QGIS: working with projections](https://docs.qgis.org/3.44/en/docs/user_manual/working_with_projections/working_with_projections.html), [ArcGIS Pro: Define Projection](https://doc.esri.com/en/arcgis-pro/latest/tool-reference/data-management/define-projection.html), and [Project](https://doc.esri.com/en/arcgis-pro/latest/tool-reference/data-management/project.html).

## 5. Basic spatial analysis

Spatial analysis uses locations and relationships to produce a result. Start with the question, then choose a tool.

| Operation | What it does | Example question |
| --- | --- | --- |
| Attribute selection | Selects records by field values | Which observations have category `rest`? |
| Spatial selection | Selects existing features by a relationship such as within, touches, or intersects | Which observations are inside a park? |
| Buffer | Creates polygons within a specified distance of input features | What area is within 300 metres of a rest observation? |
| Clip | Keeps the part of an input layer inside a mask | Which path segments lie within this study area? |
| Intersection | Creates the common parts of inputs, with attributes from both | Which park areas lie inside a rest buffer? |
| Union, for polygons | Splits inputs into areas retaining combined coverage and attributes | How do land-use and flood-zone boundaries divide the study area? |
| Difference or erase | Removes parts covered by another layer | Which park areas lie outside a flood zone? |
| Dissolve | Combines features, optionally by a shared attribute, removing internal boundaries | What is the combined area of overlapping buffers? |
| Spatial join | Attaches attributes or summaries based on location | How many observations fall in each district? |
| Raster calculation or zonal statistics | Calculates cell values or summarises them within areas | What is the mean elevation in each district? |

Start with [QGIS's buffer introduction](https://docs.qgis.org/3.44/en/docs/gentle_gis_introduction/vector_spatial_analysis_buffers.html), [overlay tools](https://docs.qgis.org/3.44/en/docs/user_manual/processing_algs/qgis/vectoroverlay.html), [spatial selection](https://docs.qgis.org/3.44/en/docs/user_manual/processing_algs/qgis/vectorselection.html), [spatial joins](https://docs.qgis.org/3.44/en/docs/user_manual/processing_algs/qgis/vectorgeneral.html), and [raster analysis](https://docs.qgis.org/3.44/en/docs/user_manual/processing_algs/qgis/rasteranalysis.html).

### Interpret the result

A 300-metre buffer around a point uses 300 metres as its radius. Around a line it forms a corridor. Overlapping buffers may remain separate records; dissolving combines their coverage. Adding separate buffer areas can double-count the shared area. A straight-line buffer does not account for bridges, fences, slopes, opening hours, or walking routes. [QGIS: Buffer and Dissolve](https://docs.qgis.org/3.44/en/docs/user_manual/processing_algs/qgis/vectorgeometry.html).

When interpreting a result, record the input date, CRS, units, distance, and relationship used. Check missing attributes and invalid geometry. A count of volunteered observations is a count of contributed records; it does not measure everyone's needs or the total number of facilities.

## 6. QGIS and ArcGIS

**QGIS** is free, open source desktop GIS for Windows, macOS, and Linux. It can display, edit, and analyse vector and raster data and create map layouts. Download it from the [official QGIS site](https://qgis.org/download/). Use the course's installed version where available; the references here use the QGIS 3.44 manual.

**ArcGIS** is Esri's GIS platform. **ArcGIS Pro** is its desktop application for Windows; **ArcGIS Online** is a separate web platform. Pro supports data editing, analysis, and layouts. Access requires an appropriate licence; use university access if provided. Some tools require particular licence levels or extensions. [ArcGIS Pro requirements](https://doc.esri.com/en/arcgis-pro/latest/get-started/arcgis-pro-system-requirements.html) and [the ArcGIS platform overview](https://www.esri.com/en-us/what-is-gis/overview).

Both desktop applications have a map view, a list of layers, attribute tables, layer properties, and analysis tools. Inspect a layer's source and CRS, open its table, and change its symbology before attempting analysis. For QGIS, start with the [training manual](https://docs.qgis.org/3.44/en/docs/training_manual/index.html) and [layer properties guide](https://docs.qgis.org/3.44/en/docs/user_manual/working_with_vector/vector_properties.html).

### The geo-toolbox

A **toolbox** groups analysis and data-management operations. **Geoprocessing** means applying such operations to geographic data. A toolbar's pan button changes the view; a Buffer tool creates a dataset.

In QGIS, choose **Processing > Toolbox**. Search for a tool and double-click it. Choose the built-in QGIS tool for this exercise; other providers can expose similarly named tools. In ArcGIS Pro, choose **Analysis > Tools** to open the **Geoprocessing** pane, then search or browse its toolboxes. [QGIS toolbox](https://docs.qgis.org/3.44/en/docs/user_manual/processing/toolbox.html) and [ArcGIS Pro geoprocessing walkthrough](https://doc.esri.com/en/arcgis-pro/latest/get-started/use-geoprocessing-tools.html).

Before pressing Run, check the input layers, geometry types, CRS, units, parameters, and output path. Read the tool's Help and review its messages afterwards. Save temporary results you want to keep; saving the project alone may leave temporary data unavailable next time.

| Task | QGIS tool name | ArcGIS Pro equivalent |
| --- | --- | --- |
| Convert vector coordinates | Reproject layer | Project |
| Make proximity areas | Buffer | Buffer |
| Keep shared geometry | Intersection | Intersect |
| Restrict to a study area | Clip | Clip |
| Combine areas | Dissolve | Dissolve |
| Relate attributes by location | Join attributes by location | Spatial Join |

Names and settings vary between versions. Compare tool documentation rather than assuming identical defaults. Esri's [Intersect](https://doc.esri.com/en/arcgis-pro/latest/tool-reference/analysis/intersect.html) and [Spatial Join](https://doc.esri.com/en/arcgis-pro/latest/tool-reference/analysis/spatial-join.html) references explain their inputs and outputs.

## 7. From desktop GIS to webGIS and digital geographies

Desktop GIS can prepare and analyse data before a web map displays it. In this course, HTML structures the page, CSS controls its appearance, JavaScript handles interaction, and Leaflet draws the map. Adding a layer to Leaflet does not perform every analysis listed above. Our [GeoJSON](geodata.md), [Leaflet](leaflet.md), and [OGC services](ogc_webservices.md) tutorials build on these GIS concepts.

Choosing to represent a park as a polygon, classify an observation as `rest`, or define "near" as 300 metres affects the geographic claim. Ask whose knowledge produced those choices and what they leave out. Connect this to the [digital geographies readings](../README.md#digital-geographies) before reporting a result as a description of people's experience.

## Exercise: inspect three points and make a buffer

Use QGIS on your computer or a teaching computer. No plugin, coding, online basemap, or new dataset is required. Keep the source file unchanged. If you cannot access QGIS yet, complete the concept questions below and return to the tool exercise when it is available.

### A. Inspect the source

1. Create `practice/gis_101` inside the course folder using your file manager. In QGIS, start a new project and save it there as `gis_101.qgz`.
2. Drag [places.geojson](../code_snippets/03_geojson/places.geojson) from your local repository into QGIS. Right-click its layer and choose **Open Attribute Table**. Identify its three features, two categories, and geometry type.
3. Select one row and find its highlighted point. Then clear the selection. Inspect **Layer Properties > Information** for the source CRS and **Source** for its definition. Expect WGS 84, EPSG:4326. If it is unknown or different, check that you opened the supplied file before continuing.

### B. Prepare metre coordinates and buffer

1. Open **Processing > Toolbox**, search **Reproject layer**, and choose the QGIS tool. Set the point layer as input and the target CRS to **WGS 84 / UTM zone 33N, EPSG:32633**. Save the output as `points_utm33.gpkg` in `practice/gis_101`.
2. Inspect the output CRS. It should use metres and contain the same three points. Set the project CRS from this output layer using its right-click menu. This changes the view; the previous step created the converted dataset.
3. Search the toolbox for the QGIS **Buffer** tool. Use `points_utm33` as input, distance **300 metres**, **Segments: 20**, and leave **Dissolve result** unchecked. Save the output as `buffers_300m.gpkg` in your practice folder. Segments controls how smoothly curved edges are approximated.
4. Put the points above the buffers in the Layers panel. Give buffers a transparent or partly transparent fill. Inspect the table: expect three polygon features. A 300-metre radius means a diameter of about 600 metres, not 300.
5. Run Buffer again at **600 metres**, saving `buffers_600m.gpkg`. Predict which buffers will share space, then compare. Run **Dissolve** on the 600-metre buffer layer with no dissolve field and save `buffers_600m_dissolved.gpkg`. Explain why one combined feature may contain several parts and why its covered area should not double-count overlaps.
6. Save the project, close it, and reopen it. Check that the saved output layers still load. Record the source file, target CRS, distances, and tool settings in `practice/gis_101/learning_log.md`.

### C. Explain the result

Write short answers in the same learning log:

1. Which part of a point feature is geometry, and which part is an attribute? What changes when you restyle it?
2. Would a satellite image be vector or raster? What can a missing raster value mean?
3. What is the difference between assigning a source CRS and reprojecting a dataset? Why did we reproject before this buffer?
4. Which operation would find the parts of park polygons shared with the buffers? Which would count observations per district?
5. Why does a buffer of an invented observation fail to establish actual walking access or the availability of seating in Graz?

You are done when your project reopens with three saved 300-metre buffer features, you can show the effect of the larger and dissolved buffers, and you can explain the geometry, attributes, CRS, and limits of the result.
